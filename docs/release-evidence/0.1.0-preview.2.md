## Repeatable lifecycle hardening run

On 2026-07-16, the post-release `windows-installer-lifecycle` scenario passed 21 of 21 gates against the immutable Preview.1 and Preview.2 MSI files and their published hashes. The elevated Windows run started with no Vault Prospector registration and proved:

- stable UpgradeCode, distinct ProductCodes, and increasing MSI versions (`0.1.1` to `0.1.2`);
- silent Preview.1 installation with one Installed apps entry, executable, and Start menu shortcut;
- silent Preview.2 major upgrade with one current-version entry;
- forced repair restored the original hash of a deliberately changed packaged `VaultProspector.App.runtimeconfig.json`;
- the Preview.1 downgrade attempt was rejected with Windows Installer exit code `1603` and Preview.2 remained installed;
- silent uninstall removed registration, executable, and shortcut while retaining a pre-existing LocalApplicationData sentinel;
- scenario cleanup removed its sentinel and left zero product registrations or installed program files.

The structured result contained `passed: true`, 21 passing gates, both artifact hashes, MSI properties, timestamps, and the Windows version. Verbose MSI logs and the JSON result remain in the ignored `artifacts/installer-lifecycle` directory because MSI logs can expose local machine paths. This run strengthens reproducibility but does not replace the required independent rerun on a clean supported VM against the final signed candidate.

A separate fail-closed test preinstalled Preview.2, invoked the scenario, and proved that the clean-start gate returned failure without uninstalling or changing the existing product. Explicit test cleanup then uninstalled Preview.2 successfully and left zero registrations. Scenario cleanup is ownership-gated and considers only the two ProductCodes supplied to that run after the scenario has begun an installation mutation.
