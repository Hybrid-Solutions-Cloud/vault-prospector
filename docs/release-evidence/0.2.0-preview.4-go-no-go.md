## Replacement rationale

Installed `0.2.0-preview.3` could not complete local unlock because it called the UWP-only request
API from an unpackaged Windows desktop application. `0.2.0-preview.4` uses the required
HWND-bound desktop interop API, retains fail-closed behavior, and explicitly explains when Windows
returns `DeviceNotPresent` in an affected Remote Desktop session.

The active Remote Desktop environment still cannot produce a Windows verification prompt. A
dedicated Windows 11 Hyper-V guest subsequently completed real local-console Windows Hello
success, cancellation, button re-entry, and button-initiated success against the exact public MSI.
Those results satisfy AB#5539's remaining condition without changing the accepted Remote Desktop
limitation.

## Accepted Preview risks

- Direct Windows binaries are not Authenticode-signed and display **Unknown Publisher**.
- Windows verification may be unavailable through Remote Desktop; users must reconnect through
  the local Windows or Hyper-V console. The application remains locked in the unavailable session.
- The first-run Identity Type selector initially shows a null conversion error. Selecting
  `InteractiveUser` clears it; AB#5542 tracks a no-workaround replacement.
- Independent security, legal/privacy, accessibility, and representative usability approvals are
  incomplete.
- Complete live Entra, Azure identity, permission, and enterprise-policy matrices are incomplete.
- Microsoft Store certification and Microsoft-signed install/upgrade evidence remain open.
- WinGet and Chocolatey catalog acceptance remain external post-publication work.

CyberArk and native mobile are separate future-roadmap releases and do not block this Windows
Preview decision.

These risks are accepted only for voluntary non-production evaluation. They do not satisfy GA.

## Rollback triggers

Withdraw this version if the required verification can be bypassed, the HWND-bound request fails
on a supported local console, artifact identity differs from the recorded hashes or bundles, the
installer corrupts or removes retained state, protected values or credentials appear in
diagnostics or artifacts, or a critical/high security defect is confirmed.

## Remaining promotion gates

The [release-readiness matrix](../product/release-readiness.md) remains authoritative. No stable or
GA promotion is permitted until its independent review, local-console and live identity/provider,
accessibility and usability, enterprise, operational, legal/privacy, and free Microsoft Store
signing gates pass with exact-candidate evidence.
