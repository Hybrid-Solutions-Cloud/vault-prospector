- Decision: GO for a replacement, explicitly unsigned, non-production Windows Preview; not ready

- Defect correction: [PR #33](https://github.com/Hybrid-Solutions-Cloud/vault-prospector/pull/33).
- Source commit: `e84d0f0e47605d9575a3306721adf3b50764c4d2`.
- Immutable tag: `v0.2.0-preview.4`.
- Public release:
  <https://github.com/Hybrid-Solutions-Cloud/vault-prospector-releases/releases/tag/v0.2.0-preview.4>.
- Published: `2026-07-25T13:20:58Z`.

This release replaces `0.2.0-preview.3`, which called the UWP-only verification request API from
an unpackaged Windows desktop application. The replacement binds Windows verification to the
application window through `UserConsentVerifierInterop` and explains the distinct
`DeviceNotPresent` result returned by Windows in an affected Remote Desktop session.
The public `0.2.0-preview.3` release is marked **WITHDRAWN — DO NOT INSTALL** and points users to
this immutable replacement; its tag and assets remain unchanged for auditability.

## Windows verification scope

Automated coverage proves that the production service passes the real application window handle
to the desktop interop API, fails closed when no handle exists, and distinguishes Remote Desktop
`DeviceNotPresent` without suggesting a futile retry. The corrected Remote Desktop message was
also observed through Windows UI Automation during diagnostic testing.

Windows returned `DeviceNotPresent` for both the UWP availability probe and the correct desktop
interop request in the active Remote Desktop session. That session therefore cannot provide a
positive Windows verification result.

The missing positive evidence was completed on 2026-07-25 in a dedicated Windows 11 Enterprise
25H2 Generation 2 Hyper-V guest with Secure Boot and vTPM enabled. Testing used basic VMConnect
console mode, not Enhanced Session or Remote Desktop. The exact public Preview.4 MSI was copied
into the guest and independently matched its published SHA-256
`8CC1E6CCC9557593DEBB72DD05F3F57F738FFF5C97981B7A2EB238BD156933AE`.
The operator workstation controlled the console but did not compile, package, or republish the
application.

| Console check | Result |
| --- | --- |
| Enroll Windows Hello PIN for a disposable local account | Passed |
| Launch Preview.4 and complete its Windows Security prompt | Passed; the application opened and reported `Local unlock complete` |
| Relaunch Preview.4 and cancel the Windows Security prompt | Passed; the application remained locked and reported `verification was canceled` |
| Select **Unlock Vault Prospector** from the canceled/locked state | Passed; the button opened a new Windows Security prompt |
| Complete the button-initiated prompt | Passed; the application unlocked and returned to the first-run workflow |

The retained screenshots contain no PIN or password. Their SHA-256 values are:

These results complete the local-console condition for AB#5539. They do not complete parent User

independent-review, and exact-release proof.

The same clean first-run session exposed a separate, non-verification defect: the **Identity
Type** selector initially rendered an `InvalidCastException` because its value was null. Opening
the selector and choosing `InteractiveUser` cleared the error. AB#5542 tracks removal of that
workaround and exact-package retesting.

## Installer and trust boundary

The release workflow validated MSI upgrade scheduling, shortcut/icon contracts, MSIX structure,
browser-host installation, and package-manager manifests. The clean Windows 11
install/upgrade/repair/downgrade/uninstall gate remains supported by the exact public
`0.2.0-preview.1` 27/27 lifecycle record; it was not repeated or relabeled as a
`0.2.0-preview.4` lifecycle run.

Direct MSI, MSIX, and ZIP packages remain intentionally unsigned and display **Unknown
Publisher**. Checksums, SBOM, and Sigstore provenance protect direct-download integrity but are
not Windows publisher trust. The no-cost trusted path remains Microsoft Store certification and a
Microsoft-signed MSIX.

## Residual risk

This replacement is still a non-production Preview. The AB#5542 first-run identity-type default,
independent security and accessibility review, representative usability, live Entra/Azure
matrices, governed enterprise deployment, legal/privacy approval, operational exercises, and
Microsoft Store acceptance remain open in the
[release-readiness matrix](../product/release-readiness.md). CyberArk and native mobile remain
separate future-roadmap releases.
